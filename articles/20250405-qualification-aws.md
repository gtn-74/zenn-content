## まとめる

- **スケールアップ**：サーバーの性能を上げる
- **スケールダウン**：サーバーの性能を下げる

---

- **スケールアウト**：サーバーの台数を増やす
- **スケールイン**：サーバーの台数を減らす

---

- **アンマネージドサービス**：素のサーバーだけをレンタルする
- **マネージドサービス**：バックアップや運用保全などを AWS 側のサービスを利用することで亜ンマネージドサービスでは、自身で管理しなければいけないことも、サービスで対応できる

**マネージドサービス注意**

マネージドサービスは、AWS が運用管理しているため、最新の環境に更新される。そのため新しいバージョンと、古いバージョンの二重管理したいといった要望に応えることが難しかったりする様子。

- **可用性**：システムが使える時間／稼働時間

メンテナンスを考慮すると 100%の可用性は難しい。

可用性は、SLA に記されている。

- `1ヶ月（43,200分）* (100 - 99.9) = 7.2h(432m)`
- `1ヶ月（43,200分）* (100 - 99.99) = 43.2m`

もしサービスを無停止で運用しなければいけない場合、システムを冗長化する仕組みが必要。

- **リージョン**：世界 32 カ国で展開されている地域のこと

AWS 利用者は、好きなリージョンに仮想サーバー、仮想ネットを構築、運用できる。

でも、ユーザーから近いリージョンである方が、通信のレスポンスが速い。

AWS を利用する場合によく用いられるサービスは多くても 10 サービス程とのこと。

## 脱線。Web サーバーを構築する

Web サーバー： HTML や API のリクエストに応答する「箱」＝物理・仮想マシンのこと

Web サーバーソフト： Apache や nginx など、リクエストを処理してレスポンスを返すソフト

1. ブラウザが .html などをリクエスト
2. Web サーバーソフト（Apache/nginx） が該当ファイルを返す
3. HTML 内の JavaScript が API を呼び出す
4. API サーバーが JSON データなどを返す
5. ブラウザが画面を描画

**昨今流行ってる Lambda、API Gateway**
EC2 は、アンマネージドサービス、プロダクトのスケールによってサーバーを人間が増減する必要がある。

Lambda、API Gateway であれば、スケーリングを AWS が自動でやってくれる。ため楽だし、コストの見通しが立てやすい様子

**S3 とは？**
マネージドなストレージサービス。データを保存、取り出すためだけに利用されるため S3 バケットとも呼ばれる。

フォームの無い、LP を作成するのであれば、S3 だけの AWS サービス利用でも問題ない。

CRUD 処理、認証など何らかの処理が必要な場合は、Web サーバーが必要らしい。そのため EC2 や Lambda みたいなものが必要になってくる様子。

S3 では、https を用い暗号化は、できない。そのため他の AWS サービスである、`Cloud Front`を用いて暗号化する必要がある。

**S3 バケットを作成してみる**

- オブジェクト：S3 バケット自体の情報、ここからファイルをアップロードしたりダウンロードしたりできる。
- プロパティ：各種設定するための画面
- アクセス許可：バケッドに対する権限付与
- メトリクス：保存されているオブジェクト数、データサイズのサマリを閲覧できる
- 管理：ストレージクラスの変更とかできる

**ホスティング？**
置き場所：Vercel、S3、Amplify、EC2 など
デプロイ：ネットに挙げる、公開的な動詞。

バケッドを作成し、ホスティングを有効にしてもデフォでは権限がないので、カスタムポリシーを記述する必要がある

[AWS Simple Storage Servie](https://docs.aws.amazon.com/ja_jp/AmazonS3/latest/userguide/WebsiteAccessPermissionsReqd.html)

```json
// 全ユーザーにread権限を付与
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": ["s3:GetObject"],
      "Resource": ["arn:aws:s3:::Bucket-Name/*"] // Bucket-Nameを変更する
      //   www.awsexample01.comとか
    }
  ]
}
```

アクセス許可のブロックパブリックアクセスのオフを解除する
